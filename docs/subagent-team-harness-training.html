Subagent Team Harness

A routing-first AI team for Salesforce solution engineers, packaged as a Claude Code plugin.

This deck explains what it is, how it works, when to use each piece, and how to adopt it honestly — for solution engineers and for the managers deciding whether it is worth rolling out.

Prepared by Anna, Creative Designer & Content Producer. Section 0 stands alone for a 2-minute read; the full deck runs about 15 minutes.

Before you read further

A Disclaimer That Matters More Than It Looks

Every persona name in this plugin — Rolando, Boris, Maggie, Richard, and the rest — is a fictional naming convention that one person invented for their own Claude Code workflow.

They are not real people, not a real Salesforce org chart, and not endorsed by Salesforce.

Read each "teammate" as a scoped prompt file with a name attached, not a colleague. That framing makes the rest of this deck easier to evaluate honestly.

What the plugin is

Two Sentences, Then the Outcome

subagent-team-harness is a Claude Code plugin that packages a routing-first AI team: one orchestrator persona that never does the work itself, plus 43 specialist personas, 19 skills, 1 slash command, and 2 workflows, each scoped to a narrow domain. Install it once, and Claude Code loads the routing table, the specialists, and the repeatable procedures into every session in the project.

Reader outcome

After this deck: an SE can pick the right tool for a task and run it. A manager can decide whether it is worth adopting for their team.

Why a team, not one assistant

Three Business Outcomes

  1. Consistency and a second pair of eyes. Two standing quality gates — Boris for technical accuracy, Maggie for pedagogy and voice — review finished work before it ships.
  2. Speed on repeatable prep work. Parallel fan-out runs several research or review steps at once instead of one at a time, for the tasks where that structure pays off.
  3. Lower ramp cost. "How we do X" lives in a persona or skill file a new team member can read, not only in one person's head.

What this is not

Honest Caveats, Stated Up Front

  • No maintainer. One person built this for their own workflow; nobody is on call for it.
  • Needs adaptation per team. Rename or delete personas, swap in your own accounts, and adjust the skills before you rely on it.
  • It drafts. Every output is a draft a human reviews and sends — it does not act unsupervised.
  • Read-only Salesforce access. Nothing it does writes back to your org.
Honest ROI framing: it removes the blank page and the re-typing. It does not replace SE judgment.

Section 1 · The mental model

The Generalist Tax

One large context window trying to do everything — account research, deck-building, risk tracking, calendar triage — pays four costs:

  • It answers less consistently call to call, because "the whole job" competes for the same context.
  • It has no second reviewer, so a weak draft ships as easily as a strong one.
  • It forgets between sessions unless someone re-explains the background each time.
  • It cannot do several independent things at once — it is one thread of reasoning.

The fix is not a smarter model. It is routing: split the work by domain and let each split hold a narrower job.

Pattern 1 of 4

Orchestrator Routes to a Scoped Specialist

A persona file scoped to one domain — say, Data Cloud architecture — carries denser, narrower context than a generalist, so its answers stay more consistent call to call. The orchestrator persona's only job is matching a request to the right file and handing off; it does not do the work itself.

Cost

43 files to maintain, and routing only helps if the table stays accurate — a stale routing table quietly misroutes work.

Pattern 2 of 4

Structural Parallel Fan-Out Via Workflow Scripts

Deterministic JavaScript orchestration — parallel(), pipeline(), agent() — turns a multi-agent fan-out into a reviewable, resumable artifact, instead of "trust the model to remember to dispatch five things." It adds schema-validated agent outputs, and can add an adversarial verification step on top — as the weekly-risk-sweep example does.

Cost

High token cost and more moving parts. Justified only when several independent surfaces genuinely need to run at once and the result needs verification.

Pattern 3 of 4

Standing Quality Gates

Two personas review finished work before it reaches a customer: Boris checks fit against Claude and Anthropic best practices — is this the simplest design, are prompts cache-friendly, is there an eval. Maggie checks pedagogy and voice — a clear takeaway, the right tone, style-guide compliance. Each returns a verdict: SHIP, REWORK, or KILL.

Cost

Every non-trivial artifact takes two extra passes before it ships. Slower, but issues get caught before a customer sees them.

Pattern 4 of 4

Persistent Per-Account Memory

The account-research skill keeps dated Markdown notes under accounts/<slug>/, so research on a specific account compounds across sessions — new signals get added to what is already known, instead of restarting from zero every time someone asks.

Cost

Memory is only as good as the discipline to keep visiting and updating it. An account nobody revisits goes stale, like any notes folder.

Section 2 · The four primitives

Four Building Blocks, One Decision Each

PrimitiveIn one line
SubagentAn isolated AI worker with its own context, tools, and model choice.
SkillA reusable procedure, auto-discovered by semantic match on the request.
Slash commandA guaranteed-fire, explicitly invoked single action.
WorkflowDeterministic JavaScript orchestration with verification and resume.

The next four slides take each one in turn: what it is, when to use it, when not to, and an example from this plugin.

The hub-and-spoke model

How a Request Gets Routed

One request in — routed to the owner, never handled by the orchestrator itself — a synthesized answer out.

Primitive 1 of 4

Subagents

What it is: an AI worker that runs in its own isolated context window, with its own scoped system prompt, tool allowlist, and model choice. It does not see the parent conversation or any sibling subagent's work — it returns a summary.

Use when: the task is self-contained and specialized, you want tool or model scoping, or you want several independent tasks running in parallel.

Do not use when: the task needs tight back-and-forth with the main thread, or it is a trivial one-liner.

Example in this plugin: dispatching the Richard subagent for a Data Cloud architecture point of view.

Primitive 2 of 4

Skills

What it is: a reusable multi-step procedure with progressive disclosure — a short, always-on description Claude sees every session (small token cost), and a fuller body that loads only when a request semantically matches.

Use when: a repeatable procedure should be auto-discoverable from natural language.

Do not use when: you need a guaranteed fire (use a slash command instead), or the "skill" is really just always-on guidance that belongs in CLAUDE.md.

Important caveat

Discovery is by semantic match, so a skill is not guaranteed to fire — loose or unusual phrasing can miss it.

Example in this plugin: pre-call-prep, triggered by "prep for [account] meeting."

Primitive 3 of 4

Slash Commands

What it is: a guaranteed-fire, explicitly invoked action, typically single-purpose.

Use when: timing or certainty matters more than loose natural-language phrasing.

Do not use when: the task is exploratory or has no fixed single action to run.

Example in this plugin: /account-summary-update [account] — a guaranteed path to the account-summary run.

Primitive 4 of 4

Workflows

What it is: deterministic JavaScript that holds the orchestration logic itself — branching, parallelism, verification — instead of Claude deciding turn by turn what to dispatch.

Benefits over hand-dispatching subagents: repeatable orchestration, schema validation on agent outputs, and resume-from-cache, where re-running skips unchanged steps. A workflow can also add an adversarial verify pass — as the weekly-risk-sweep example does — though not every workflow includes one.

Use when: parallelism or verification materially matters — several independent agents feeding one synthesized result.

Do not use when: the task is one to three items, or needs mid-run human input.

Cost

High token cost. This is the heaviest of the four primitives — reach for it deliberately, not by default.

A rule that has no exception

How One Subagent's Output Feeds Another

Subagents do not share memory. The orchestrator or workflow script captures one subagent's output and carries it into the next subagent's input — there is no direct link between subagents.

Worked example, part 1

weekly-risk-sweep: Fan-Out and Verify

Phase 1 — Fan-out

Six personas read six independent surfaces in parallel. Each returns schema-validated structured signals labeled high-risk, watch, or noise. If all six come back empty, the run short-circuits right here — before verify, synthesize, or gate ever run — and produces no brief at all.

Phase 2 — Verify

Each high-risk candidate goes to a skeptical reviewer whose job is to refute it. The default is "refuted" when a claim cannot be substantiated — an unsupported high-risk line is worse than a missing one.

Worked example, part 2

weekly-risk-sweep: Synthesize and Gate

Phase 3 — Synthesize

Matija writes a one-screen brief. Refuted lines get demoted to a noise log with the refutation reason. Any line that exceeded the verification cap is marked "(unverified)" rather than presented as confirmed.

Phase 4 — Gate

An anti-pattern check fails the brief if it contains alarmist language, missing citations, or missing required sections.

Takeaway

This is what "structural, verified fan-out" actually looks like: parallelism, plus a built-in skeptic, plus a rule against padding.

Putting it together

Which Primitive Do I Reach For?

  1. Need a guaranteed-fire, explicitly named action? → Slash command
  2. Repeatable multi-step procedure that should auto-discover from phrasing? → Skill
  3. Self-contained, specialized, or independently parallel task? → Subagent
  4. Verification matters, and results must be synthesized from more than one independent surface? → Workflow
  5. None of the above? → Just ask, in the main thread

Section 3 · A day in the life of an SE

Six Moments, Six Tools

Not every task needs the heaviest hammer. Here is how a normal week of SE moments maps to the right primitive.

Monday, before standup

"What's Slipping This Week?"

Tool: weekly-risk-sweep workflow

You want a read on what is at risk across your accounts before the week starts.

Why a workflow: six surfaces, verified, synthesized into one brief — exactly the five-or-more-agent, verification-matters case a workflow is built for.

Two hours out

A Customer Call Is on the Calendar

Tool: pre-call-prep skill

You have not looked at the account yet and the call is in two hours.

Why a skill: a repeatable one-page prep procedure, auto-discovered from "prep for [account] meeting" — no command to remember.

Mid-conversation with a prospect

A Pointed Data Cloud Architecture Question

Tool: dispatch the Richard subagent

You want a specialist's point of view before you answer.

Why a subagent: self-contained and specialized — a scoped persona, no need to share context back and forth with the main thread.

Next week's business review

Building a Customer Deck

Tool: deck-build skill

You need a client-specific deck, with Anna producing visuals and Maggie gating the final copy.

Why a skill plus a gate: a repeatable multi-step procedure — template copy, visuals, population, review — that benefits from a standing quality check before it goes to a customer.

You just picked up a new account

Research That Needs to Compound Over Months

Tool: /account-research

You want a place to keep research, brainstorms, and pipeline notes that persists across sessions.

Why persistent memory: the one case built for memory that compounds — dated Markdown notes under accounts/<slug>/, not a one-shot brief.

Right after the call ends

Drafting the Recap Before You Forget It

Tool: post-call-followup skill

You want a recap drafted and posted before the details fade.

Why a skill: draft, then voice-gate, then post, then verify — one guided procedure, with a human still reviewing before anything ships.

The other half of good judgment

When Not to Reach for the Team

  • A trivial one-liner — "what's today's date," "convert this to title case." Just answer it.
  • Anything needing live human judgment mid-task — a negotiation call, a read on a client's tone in the room.
  • Anything that would post, send, or commit without review. Every output in this plugin is a draft; nothing auto-sends.

Section 4 · Getting started

Install It

/plugin marketplace add derickafrica-public/subagent-team
/plugin install subagent-team-harness@subagent-team-harness

Two commands, run once per environment.

Setup is a start, not a finish

Run Setup, Then Finish by Hand

The scaffold step (setup.sh) creates the folder structure and default config, but it does not finish the job on its own. Plan on manual follow-ups:

  • Add generated-output folders to .gitignore.
  • Authenticate any MCP connections you wire in — Salesforce, Slack, Google Workspace.
  • Decide whether you want any scheduled jobs turned on. None are required to start.

Make it yours

Adapt It — Do Not Adopt It As-Is

This was built for one person's team and accounts. Before you rely on it:

  • Rename or delete personas you do not need — 43 is a lot; most teams need a fraction.
  • Strip the Salesforce-specific content if you are not an SE.
  • Wire in your own accounts and Salesforce org instead of the examples in this deck.

Maintenance, not magic

Keeping Skills Fresh so Personas Don't Go Stale

weekly-skills-refresh keeps persona files current without a human re-researching each one by hand. It fires on the trigger phrases "refresh team skills," "update team Salesforce skills," or "run weekly skills refresh" — and headlessly every Saturday at 22:00 via the com.rolando.weekly-skills-refresh launchd job. One teammate, Roman, runs the entire pass in a single turn.

Each run scans two parallel team rosters — two separate personas-with-files setups — for Salesforce, Agentforce, and Data Cloud capabilities published in roughly the past seven days: official release notes, product blogs, and a targeted web search across items mentioning Agentforce, Data Cloud, Einstein, Flow/Apex/LWC, Tableau, MuleSoft, Informatica, and similar surfaces.

Before writing anything, it checks each finding against what was already appended in prior weeks and drops duplicates. It then classifies each surviving finding to the correct owner per roster independently — the same capability can map to a different owner in each roster, or to only one roster if the other has no matching specialist.

Findings land as dated bullets under a ## Recent Capability Updates heading in each affected persona file — prepended above older weeks, never deleted — so each file accumulates a real history. Every bullet carries a one-sentence description and a source URL; nothing gets written without a verifiable source. Each run also writes one combined log with counts per persona and the full list of sources consulted.

Honest framing

If a source is unreachable, the run log says which one failed — it does not fabricate a capability to fill the gap, and it exits cleanly rather than retry-looping. Freshness still depends on Roman's sources staying wired up; nothing here rewrites a stale persona on its own.

The line that matters most

Safety Posture

  • Every output is a draft. A human reviews and sends everything the team produces.
  • Salesforce org access is read-only everywhere it is wired in.
  • Nothing auto-posts, auto-sends, or auto-commits without a review step in front of it.

Closing

You Own It Now

This deck describes a snapshot of one person's working setup. Nobody maintains it centrally — if you adopt it, you become the maintainer of your copy.

That is not a warning meant to scare you off. It is the honest tradeoff for a tool made of readable files instead of a black box: you can open any persona, skill, or workflow and change it. Rename what does not fit. Delete what you do not need. Extend what earns its place.

It drafts. You decide.
